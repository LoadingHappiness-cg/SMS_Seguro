# Remote Enrichment Controlled Smoke Test

## Controlled enablement

Remote enrichment stays **off by default** in every normal build.

It can only be activated in `debug` builds by passing explicit Gradle properties or environment variables:

```bash
./gradlew assembleDebug \
  -PSMS_SEGURO_REMOTE_ENRICHMENT_DEBUG_ENABLED=true \
  -PSMS_SEGURO_REMOTE_ENRICHMENT_DEBUG_BASE_URL=http://10.0.2.2:8787
```

Optional trace toggle:

```bash
./gradlew assembleDebug \
  -PSMS_SEGURO_REMOTE_ENRICHMENT_DEBUG_ENABLED=true \
  -PSMS_SEGURO_REMOTE_ENRICHMENT_DEBUG_BASE_URL=http://10.0.2.2:8787 \
  -PSMS_SEGURO_REMOTE_ENRICHMENT_DEBUG_TRACE=true
```

Equivalent environment variables:

- `SMS_SEGURO_REMOTE_ENRICHMENT_DEBUG_ENABLED=true`
- `SMS_SEGURO_REMOTE_ENRICHMENT_DEBUG_BASE_URL=http://10.0.2.2:8787`
- `SMS_SEGURO_REMOTE_ENRICHMENT_DEBUG_TRACE=true`

Release and releaseUnsigned builds keep:

- `REMOTE_ENRICHMENT_ALLOWED=false`
- `REMOTE_ENRICHMENT_ENABLED=false`
- `REMOTE_ENRICHMENT_TRACE=false`

## Internal trace path

Only when the debug-controlled path is enabled, the app emits compact logcat lines with tag `SMS_SEGURO`:

```bash
adb logcat -s SMS_SEGURO | grep RemoteEnrichment
```

Expected examples:

- `RemoteEnrichment success host=example.com dnsBlocked=false delta=0 reasons=`
- `RemoteEnrichment fail_open host=example.com error=SocketTimeoutException`
- `RemoteEnrichment skip invalid_host value=https://bad.example/path`

No user-facing toast, dialog, or extra notification should appear for remote failures.

## Smoke scenarios

### 1. Valid benign host

Input SMS example:

```text
Veja os detalhes em https://example.com
```

Expected:

- local analysis still runs first
- remote enrichment succeeds
- `dns_blocked=false`
- score remains unchanged or only remote benign delta `0`
- no scary new UX
- trace shows `success`

### 2. Suspicious or malicious host

Input SMS example:

```text
Pagamento pendente em https://<known-test-host>
```

Expected:

- local analysis runs first
- remote enrichment returns `remote_dns_blocked` if Quad9 blocks the host
- merged score increases
- UI reasons include remote reason text only on success
- trace shows `success ... dnsBlocked=true`

Note:

- use a host already known to be blocked by Quad9 in a safe test environment
- do not use random live phishing domains in ad hoc testing

### 3. Backend timeout

Point the app to a stub endpoint that accepts TCP but sleeps longer than `1500ms`.

Expected:

- local result still appears normally
- no user-facing error
- no crash
- trace shows `fail_open ... SocketTimeoutException`

### 4. Backend unavailable

Use a port with no service, for example `http://10.0.2.2:8799`.

Expected:

- local result still appears normally
- no user-facing error
- trace shows `fail_open`

### 5. Invalid host

Use an SMS with malformed URL host handling, for example:

```text
Abra https://bad host ou https://bad.example/path extraído incorretamente
```

Expected:

- if the extracted host is invalid, remote enrichment is skipped
- no network call
- trace shows `skip invalid_host`

### 6. Malformed backend response

Run a temporary stub that returns invalid JSON or the wrong shape.

Example stub:

```bash
python3 - <<'PY'
from http.server import BaseHTTPRequestHandler, HTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.end_headers()
        self.wfile.write(b'{"oops":true')

HTTPServer(("127.0.0.1", 8788), Handler).serve_forever()
PY
```

Expected:

- app keeps the local result
- no user-facing error
- trace shows `fail_open`

## Execution checklist

1. Build a debug APK with explicit enablement.
2. Install on emulator or internal test device.
3. Start backend or stub for each scenario.
4. Trigger SMS test payload.
5. Capture:
   - screenshot of result screen
   - logcat snippet with `RemoteEnrichment`
   - backend terminal output if relevant
6. Confirm release build still compiles with remote enrichment off.
